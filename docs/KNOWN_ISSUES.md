# Known issues

- The source preview requires a pinned downstream Harness fork; stock `0.1.2-rc.1` does not expose Presentation protocol 2.
- Multi-Pane membership is process-local. Reload restores one Pane.
- The product limit is two visible Panes. A third Session replaces the focused Pane.
- Narrow viewports display only the focused Pane while retaining the other tree in memory.
- Open Beside applies to listed Sessions, not addressed subagent children.
- Better Sidebar Pane support requires the optional pinned fork, **which does not load on this release's Harness pin** — see the entry below before touching it. Unknown global overlays are never moved by DOM heuristics.
- The in-place quote band (the tint and underline over a quoted passage) is painted with the CSS Custom Highlight API and has **no fallback path**. On a runtime without `CSS.highlights` nothing is painted and nothing warns; the numbered badges, the quote list behind the composer chip, the note cards, and the serialized message all keep working, so what is lost is only being able to see which passage a quote points at. The Harness pins a Chromium that has the API, so this bites only unusual embeddings.
- A quote whose passage leaves the conversation goes `detached`: its band and badge disappear and the note can no longer be reached from the body. The quote and its note are **still sent with the message**, and the row stays editable in the quote list behind the composer chip, which is the only path to it in that state.
- There is no way to jump from a quote back to its source passage from inside an open note card. The card's action row is delete and save only. Scroll-to-source still exists from the quote list.
- **The pinned Better Sidebar fork does not load on this release's Harness pin, and taking it down takes the whole harness with it.** `dsh-better-sidebar` 0.16.1 at commit `168577078bf63a16cb514e879669298565991b07` was built against the previous upstream baseline and imports `settingsNamespace` from `@deepseek-ai/dsh-settings`, an export upstream deleted in the baseline this release pins. The loader throws while building the plugin tree, so the harness fails to boot entirely — `plugin tree failed to load … does not provide an export named 'settingsNamespace'` — rather than merely losing the sidebar. Workbench's own Host entry made the equivalent adaptation; the fork has not. `docs/INSTALL.md` §4 and `release-contract.json`'s `panelCompatibility` block still name that commit, both now carrying a warning: **do not install it**. Pane-local panels are unavailable until a fork rebuilt against the pinned baseline is published and pinned. If a harness stopped booting after §4, remove `dsh-better-sidebar` from the profile and restart.
- The Workbench `v0.2.0-rc.6` GitHub Release is published with SHA256-verified (not GPG-signed) TGZ and bootstrap-script assets; npm publication is not planned. `docs/INSTALL.md` § Quick Install now works directly. `docs/INSTALL.md` § Advanced: source build remains available for anyone who wants to obtain and approve a full 40-character Workbench commit through an independent trusted channel and build from source themselves.
- The Split Pane bootstrap installer has one isolated end-to-end run behind it, on Windows, against the withdrawn `v0.2.0-rc.4` installer, which pinned Harness `c5a387cd` — the same pin this release carries: the published script was downloaded from the release, verified against `SHA256SUMS`, and run against a clean, deliberately space-containing target with no `-TgzSha256`; it reported `state: installed` / exit 0, and the detached checkout, TGZ digest, self-relative launcher and untouched real `~/.dsh` were each confirmed afterwards. That run cloned from GitHub directly, so reachability is evidenced — one attempt did fail on a transport reset first, and the installer failed closed with a valid result JSON and exit 1. The earlier `v0.2.0-rc.2` run had to substitute a local mirror after repeated resets, so it proved installer correctness but not reachability; the `v0.2.0-rc.3` installer was never run. **Split Pane was not exercised in that isolated run** — the isolated home has no configured model — but it is no longer unevidenced: `v0.2.0-rc.6` drove Split Pane and quote-badge placement through a browser on a real `~/.dsh` running this same pinned fork (Ctrl-click produced two `[data-session-pane]`; the badge cleared the turn rail by 145px in a 1440px viewport). The general-plugin path and read-only-`$DSH_HOME` degradation have never run on any platform, macOS has never had an isolated run, and Linux remains unverified and unsupported. See [`docs/COMPATIBILITY_MATRIX.md`](COMPATIBILITY_MATRIX.md) § Outstanding verification.
- On Node `24.0`–`24.11.1`, releases up to and including `v0.2.0-rc.3` served an empty client module graph (`__DSH_BOOT__.entries: []`), so the client half of every plugin — the Workbench included — never mounted, behind swallowed or warn-level errors. The cause is upstream: those Node versions report major 24 while still carrying the v1 internal module-loader API, and the loader shim classified by major version, so `resolveSync` was called with reversed parameters and every call threw. Upstream fixed it in `0.1.2-rc.1` by classifying the loader by which module-job API it owns, and the current pin carries that fix. On an affected Node with an earlier release, the workaround is Node `24.12+` or the `^22.19` line. Not reproduced locally; this entry follows the upstream fork's own `vendor/README.md` record of the fix.
- GitHub Actions are disabled. Maintainers and contributors must attach local `pnpm release:check` evidence to changes.
