# Known issues

- The source preview requires a pinned downstream Harness fork; stock `0.1.2-rc.1` does not expose Presentation protocol 2.
- Multi-Pane membership is process-local. Reload restores one Pane.
- The product limit is two visible Panes. A third Session replaces the focused Pane.
- Narrow viewports display only the focused Pane while retaining the other tree in memory.
- Open Beside applies to listed Sessions, not addressed subagent children.
- Better Sidebar Pane support requires the optional pinned fork. Unknown global overlays are never moved by DOM heuristics.
- The in-place quote band (the tint and underline over a quoted passage) is painted with the CSS Custom Highlight API and has **no fallback path**. On a runtime without `CSS.highlights` nothing is painted and nothing warns; the numbered badges, the quote list behind the composer chip, the note cards, and the serialized message all keep working, so what is lost is only being able to see which passage a quote points at. The Harness pins a Chromium that has the API, so this bites only unusual embeddings.
- A quote whose passage leaves the conversation goes `detached`: its band and badge disappear and the note can no longer be reached from the body. The quote and its note are **still sent with the message**, and the row stays editable in the quote list behind the composer chip, which is the only path to it in that state.
- There is no way to jump from a quote back to its source passage from inside an open note card. The card's action row is delete and save only. Scroll-to-source still exists from the quote list.
- The Workbench `v0.2.0-rc.4` GitHub Release is published with SHA256-verified (not GPG-signed) TGZ and bootstrap-script assets; npm publication is not planned. `docs/INSTALL.md` § Quick Install now works directly. `docs/INSTALL.md` § Advanced: source build remains available for anyone who wants to obtain and approve a full 40-character Workbench commit through an independent trusted channel and build from source themselves.
- The Split Pane bootstrap installer has one isolated end-to-end run behind it, on Windows, against the `v0.2.0-rc.4` installer, which pins Harness `c5a387cd`: the published script was downloaded from the release, verified against `SHA256SUMS`, and run against a clean, deliberately space-containing target with no `-TgzSha256`; it reported `state: installed` / exit 0, and the detached checkout, TGZ digest, self-relative launcher and untouched real `~/.dsh` were each confirmed afterwards. That run cloned from GitHub directly, so reachability is evidenced — one attempt did fail on a transport reset first, and the installer failed closed with a valid result JSON and exit 1. The earlier `v0.2.0-rc.2` run had to substitute a local mirror after repeated resets, so it proved installer correctness but not reachability; the `v0.2.0-rc.3` installer was never run. **Split Pane itself remains unexercised in a browser**: the isolated home has no configured model, so a second session could not be created, and quote-badge placement against the host's turn rail is unevidenced for the same reason. The general-plugin path and read-only-`$DSH_HOME` degradation have never run on any platform, macOS has never had an isolated run, and Linux remains unverified and unsupported. See [`docs/COMPATIBILITY_MATRIX.md`](COMPATIBILITY_MATRIX.md) § Outstanding verification.
- On Node `24.0`–`24.11.1`, releases up to and including `v0.2.0-rc.3` served an empty client module graph (`__DSH_BOOT__.entries: []`), so the client half of every plugin — the Workbench included — never mounted, behind swallowed or warn-level errors. The cause is upstream: those Node versions report major 24 while still carrying the v1 internal module-loader API, and the loader shim classified by major version, so `resolveSync` was called with reversed parameters and every call threw. Upstream fixed it in `0.1.2-rc.1` by classifying the loader by which module-job API it owns, and `v0.2.0-rc.4` picks that up through the pin advance. On an affected Node with an earlier release, the workaround is Node `24.12+` or the `^22.19` line. Not reproduced locally; this entry follows the upstream fork's own `vendor/README.md` record of the fix.
- GitHub Actions are disabled. Maintainers and contributors must attach local `pnpm release:check` evidence to changes.
